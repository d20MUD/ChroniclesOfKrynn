# Preferred class perk routing

Study option A now includes a saved martial preference: Warrior, Berserker, Paladin, Blackguard, Ranger or Monk. Arcane and divine options retain their existing lists. New characters and missing player-file fields default to unset; opening Study no longer silently chooses Wizard/Cleric. Existing valid choices are retained. An unset or invalid preference is automatically filled when exactly one eligible base class in that category has positive class ranks. Zero or multiple candidates remain unset for manual selection. This runs after player loading and level advancement, before preference-menu display, and before perk routing/readiness checks. It counts actual class ranks, not prestige caster progression, and never overwrites an existing valid choice.

The native two-tree resolver supplies the categories to replace with preferences. Wizard/Sorcerer/Bard/Summoner assignments use the arcane preference; Cleric/Druid/Inquisitor assignments use divine; the six martial classes use martial. Rogue and other fixed trees remain unchanged. Single-tree awards retain both points. Dragon Disciple keeps its native highest-base-class selection before category substitution; Loremaster keeps its existing advancement-based routing when both assignments are identical.

A shared readiness check rejects dependent GAIN choices before changing the current class, stages, XP or levels. Class availability and automatic level advancement use the same guard. Stage progression pauses atomically when preferences are missing, preserving accumulated XP and stage counters. Both point assignments resume once configured. Perk timing remains two points per quarter-level XP stage, three awards per level; this does not add a new award on GAIN.

The optional ASCII player tag `PCMa` saves martial preference; no SQL player schema changes are needed. Arcane/divine choices retain `PCAr`/`PCDi`. Changing preferences routes future awards and does not move earned points or purchases. Previously earned pools remain usable; legacy historical compensation retains native routing.

Help source: `lib/text/help/preferred_classes.hlp`; matching database migration: `sql/20261118_preferred_classes_help.sql`. The migration is not applied automatically. No live database changes or server restart are part of this change.

Validation: `unittests/test_preferred_perks.sh` exercises production routing, automatic defaults for zero/one/multiple ranked candidates, preservation of explicit choices, all six martial options, both requested Arcane Archer examples, arcane/divine/martial and fixed-Rogue combinations, invalid/unset preferences, atomic stage catch-up, duplicate-award prevention, and unchanged previously earned pools. Set `PERK_TEST_FLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer'` to run with sanitizers.
